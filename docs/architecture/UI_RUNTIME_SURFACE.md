# UI Runtime Surface

Directive's UI is a concise projection of accepted state. It does not expose internal analysis, raw evidence, proposal confidence, hidden facts, or maintenance workflows.

The ship icon beside SillyTavern's send controls is the single launcher. The expanded interface has five routes:

- Campaign: current campaign identity, story position, and playable/preview campaign cards.
- Mission: visible objectives, optional/conditional labeling, progress, known facts, visible outcomes, terminal result, and the canonical ship chronometer.
- People: Command Bearing reserve/use/cancel, public records for authored and directly named emergent contacts, current qualitative relationships, and complete expandable defining-moment histories.
- Ship: identity, capability summary, one operational aggregate, material limitations, and mission-linked readiness.
- Settings: tooltip preference, SillyTavern-native provider policy, preset state, read-only V1 role routing, storage verification, and privacy-bounded support export.

Each fact has one primary home. Mission titles are not repeated on People cards. Mention-level ship observations are not listed. Campaign previews cannot be selected unless a complete V1 package exists. Errors use concise fail-closed empty states; the UI never offers manual semantic editing or reconciliation.

The composer launcher, responsive shell, and route hierarchy are V1 product requirements. Any future visible element must justify its player value and identify which existing surface it replaces or why no existing surface can own it.
