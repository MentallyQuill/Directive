This feature is verified with deterministic providers and local browser fixtures. No paid provider calls or live SillyTavern soak sessions were performed. Provider accuracy, real-player correction burden, and live reply latency remain unmeasured.

## Review-driven regressions

Review identified and drove checks for initially hidden objectives disappearing after manual resolution, historical evidence creating proposals during reconstruction, aborted provider responses attempting to commit before a queued correction, dialog Escape bubbling to the shell, obsolete mission-complete notifications surviving a correction, manual disposition replacement retaining conflicting outcome evidence, and replay rejecting the first later evidence gated on a player-set objective. These are behavioral checks, not accuracy measurements for the interpreter model.

## Product boundaries

- The player controls only the active mission occurrence. Earlier missions require checkpoint recovery.
- A correction that cannot retract credited Command Bearing from the current balance is rejected with a checkpoint explanation; it does not create negative credit or undo later play.
- Manual dispositions are explicit decisions, not fabricated narrative facts. Separate outcome-dependent requirements may still need actual evidence.
- A reopened objective requires confirmation for later proposals. The interpreter's materially-new-evidence judgment remains model-assisted; it is not an adversarial guarantee.
- Evidence explanations use accepted source excerpts. This feature does not add a SillyTavern message-navigation API.
- No backward-compatibility or migration layer was added for progress decisions.
