# Story

Story Settlement owns accepted contributions, scene-sized episodes, working capsules, semantic boundary evaluation, source-backed People events, qualitative relationship state, character moments, ship effects, supersession, and player/prompt projections.

Ordinary back-and-forth does not create separate records. Mission state remains authoritative for objectives and outcomes; Story Settlement records only durable story meaning. Canonical elapsed time remains separate accepted-time custody.

The accepted-pair Utility interpreter and Reasoning story director analyze the same captured turn concurrently. The interpreter owns evidence, time, People observations and player participation. The director records consequential continuity additions and selects one bounded next-beat instruction. It also performs due retrospective episode and relationship review using only already committed evidence. Pure preparation combines both results before one state gateway commit; native narration waits for both. No model reconciliation request or post-narration episode-evaluator request is made.

Continuity events distinguish narrated facts, character claims and player commitments from authored campaign rules. Every event retains selected-source quotes and contribution dependencies. The director sees a complete unresolved-thread index, bounded details and player-safe opportunities derived from the current authored mission. Invalid or oversized output blocks narration. This constrains subsequent expansion; it does not guarantee that a narrator never invents something or that every semantic extraction is correct.

A direct NPC introduction creates an identity-stable event only after the NPC gives the player a usable name. Optional public dossier authoring runs from a persisted queue at an idle boundary on hosts with independent request transport. Starting the next turn cancels pending authoring. Results are staged and merged under the timeline lease, filling only missing fields after rechecking identity and source lineage. Failed jobs retain a usable minimal record and require explicit technical retry.

Story Settlement stores every surviving defining moment with source custody. The People page exposes the complete history, while narration receives a separately bounded recent subset. Source invalidation prunes People events, relationship effects, and moments through the same deterministic rebuild path as other story authority.
